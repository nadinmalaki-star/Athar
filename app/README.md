# لوحة الحجوزات — تطبيق موبايل

تطبيق حجوزات (React Native / Expo) لصالونات التجميل، متعدد الصالونات (multi-tenant): كل صالون بياناته معزولة عن الثاني، وميزته الأساسية هي **بصمة تفاعل العميلة** — تصنيف سلوكي واضح القواعد (تابعي الآن / انتظري / السعر عائق / فقدت الاهتمام) مبني على أنماط الحجز والتصفح والتواصل، مش تخمين ولا تحليل نفسي.

## الإعداد

1. **أنشئي مشروع [Supabase](https://supabase.com) جديد.**
2. **طبّقي السكيما**: انسخي محتوى `supabase/migrations/0001_init.sql` ثم `supabase/migrations/0002_booking_notes.sql` بالترتيب، وشغّليهم من SQL Editor بمشروع Supabase (أو عبر `supabase db push` إذا مربوطة بـ Supabase CLI).
3. **متغيرات البيئة**: بمجلد `app/`، انسخي `.env.example` إلى `.env` وعبّي القيم من إعدادات مشروعك (Project Settings → API):
   ```
   EXPO_PUBLIC_SUPABASE_URL=...
   EXPO_PUBLIC_SUPABASE_ANON_KEY=...
   ```
4. **التشغيل**:
   ```bash
   cd app
   npm install
   npx expo start
   ```
   افتحيه بتطبيق Expo Go على موبايلك أو بمحاكي.

> **ملاحظة RTL**: التطبيق بيفرض الاتجاه من اليمين لليسار (`I18nManager.forceRTL`) — أول مرة بتشتغل، ممكن يحتاج التطبيق يعيد التشغيل مرة وحدة لحد ما الاتجاه ينطبق (قيد من نظام التشغيل نفسه، مش من Expo).

## بنية المشروع

```
app/src/
  lib/            عميل Supabase + أنواع TypeScript مطابقة للسكيما
  context/        AuthContext (الجلسة، البروفايل، organizationId لصاحبة الصالون)
  navigation/     التنقّل: Auth / Owner (تبويبات: العميلات، الكاليندر) / Customer (تبويبات: الصالونات، حجوزاتي)
  screens/auth/   تسجيل دخول + حسابين (صاحبة صالون / عميلة)
  screens/owner/  قائمة العميلات + بصمة كل عميلة + شاشة "ليش هيك التصنيف؟" + الكاليندر
  screens/customer/  تصفح الصالونات، الخدمات، الحجز (مع ملاحظة اختيارية)، حجوزاتي
  domain/         منطق نصوص البصمة (fingerprintCopy.ts) — مرآة لقواعد قاعدة البيانات
  theme.ts        الألوان والخطوط والمقاسات (تصميم مبدئي، لسا قيد التطوير)

supabase/migrations/   سكيما قاعدة البيانات بالترتيب (SQL خام، يطبَّق يدوياً حالياً)
```

## وين تعدّلي قواعد التصنيف

قواعد "بصمة العميلة" (متى تابعي الآن / انتظري / السعر عائق / فقدت الاهتمام) معرّفة بمكان واحد: الـ view اسمها `customer_fingerprints` بملف `supabase/migrations/0001_init.sql` — كل حد أدنى (مثلاً "3 مرات خلال أسبوعين"، "10 أيام بدون تفاعل") موثّق هناك بالكومنتات.

نفس الأرقام بترجع تنعرض للمستخدمة بشاشة "ليش هيك التصنيف؟" عن طريق `app/src/domain/fingerprintCopy.ts` (دالة `rulesFor`) — **إذا عدّلتي عتبة بقاعدة البيانات، عدّلي نفس الرقم بهاد الملف** عشان الشرح يضل مطابق للواقع.

## شو موجود وشو لسا

**جاهز وشغّال:**
- تسجيل دخول/حساب لصاحبة صالون أو عميلة، معزولين عن بعض بالكامل (Row Level Security على مستوى قاعدة البيانات، مش بس بالتطبيق)
- قائمة العميلات + تفاصيل كل عميلة + شرح التصنيف + إمكانية صاحبة الصالون تعدّل التصنيف يدوياً
- تصفح الصالونات، الخدمات، الحجز (مع حقل ملاحظة حرة للعميلة)، وقائمة حجوزاتها
- كاليندر حجوزات لصاحبة الصالون (يوم / شهر / سنة)

**لسا مش مبني (خطوات جاية):**
- تسجيل المكالمات كإشارة تفاعل (تصميمها جاهز، ما انربطت بالكود لسا) — يحتاج نوع حدث جديد بجدول `interaction_events` وشاشة تسجيل نتيجة المكالمة
- شاشة لصاحبة الصالون تضيف/تعدّل خدماتها من داخل التطبيق (حالياً الخدمات تنضاف يدوياً بقاعدة البيانات)
- التصميم البصري النهائي — الشاشات شغالة بستايل مبدئي، والاتجاه البصري (ألوان، خطوط) لسا قيد النقاش
- موظفات إضافيات لنفس الصالون (السكيما جاهزة لهيك — جدول `memberships` بيسمح بأكتر من عضو — بس ما في واجهة لدعوة موظفة لسا)
- إشعارات، دفع إلكتروني، تأكيد حجز تلقائي
